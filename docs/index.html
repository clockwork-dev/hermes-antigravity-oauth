PROCESS TOPOLOGY

End-to-End Execution Flow

How user prompts travel through isolation boundaries to Google Antigravity models.

STEP 01 Caller

Hermes Agent Core

Accepts user prompt and tool context. Resolves requested model and dispatches turn to plugin profile.

Protocol: ProviderProfile IPC
STEP 02 Plugin Layer

hermes-antigravity-oauth

Sanitizes process environment, routes token isolation into ~/.hermes/, and supervises warm worker.

Isolation: Clean Subprocess Env
STEP 03 Local Daemon

Google Antigravity CLI

Official agy daemon. Handles local PKCE OAuth token refresh and streams NDJSON across standard pipes.

Transport: stream-json (stdin/stdout)
STEP 04 Remote Ingress

Google Cloud Ingress

Direct HTTPS / gRPC connection to Google Cloud Code endpoints with user OAuth bearer token. Zero middleman proxies.

Target: cloudcode.googleapis.com

INSTALLATION & RUNTIME

Quickstart Guide

Get up and running in under 2 minutes. Requires Hermes Agent 0.21.4+ and Google Antigravity CLI.

1. Verify Prerequisites

Ensure Hermes Agent and the Antigravity CLI are present on your PATH: 

hermes --version
agy --version
2. Install the Plugin

Install and enable via the native Hermes package manager: 

hermes plugins install \
  clockwork-dev/hermes-antigravity-oauth \
  --enable
3. Start Chatting

Launch interactive chat specifying any Antigravity model: 

hermes chat -m antigravity/gemini-3.8-flash

# Or with deep thinking:
hermes chat -m antigravity/gemini-4-argon
SECURITY GUARANTEE

Zero-Exfiltration Architecture

Your tokens, credentials, and code prompts never touch third-party servers.

Direct-to-Google OAuth

Authentication follows standard RFC 7636 PKCE. Code exchanges happen directly with Google account endpoints.

Local Token Custody

Tokens are stored isolated in ~/.hermes/antigravity-oauth/ with strict user file permissions (0600).

Environment Sanitizer

Subprocess spawner strips all ambient API keys and authentication tokens before launching the agy binary.
